# v2 구현 계획

이 문서는 v1.2.4 코드를 기준으로 정리한 구현 계획입니다. 작업 단위 A는 v1.2.5에서 완료했습니다. 밤·투표 판정 전체 분리와 AI·멀티플레이 기능은 아직 구현되지 않았습니다. 현재의 솔로 게임을 유지하면서 규칙 엔진 분리, 선택형 AI 대사, 서버 기반 혼합 참가자 게임 순으로 확장합니다.

## 현재 구조와 먼저 해결할 문제

| 현재 코드 | 현재 책임 | 분리할 책임 |
| --- | --- | --- |
| `useMafiaGame.ts` | React 상태, 역할 배정, 밤·투표 판정, NPC 행동, 메시지, 프로필 저장 | 규칙 엔진, NPC 의사결정, UI 연결 |
| `types.ts`의 `Player` | 숨겨진 역할을 포함한 전체 참가자 정보 | 서버 내부 상태와 참가자별 공개 상태 |
| `progression.ts`, `results.ts` | 업적·프로필 갱신, 진영별 승패 판정 | 솔로 보상 흐름 유지, 멀티 보상은 별도 정책 확정 후 도입 |
| `GameMain`, `Sidebar`, `ResultCard` | 로컬 상태를 표시하고 행동 콜백 실행 | 공개 상태 표시와 명령 전송 |

현재 솔로 모드는 브라우저가 NPC 역할까지 보유하고 화면에서만 숨깁니다. 이 구조를 그대로 공유하면 다른 참가자의 역할도 전달됩니다. 멀티플레이에서는 서버가 전체 상태를 보관하고 각 참가자에게 허용된 정보만 보내는 구조가 필요합니다.

## 1단계: 솔로 규칙 엔진 분리

첫 구현 단위는 외부 서비스가 필요 없는 순수 TypeScript 규칙 엔진입니다. React 상태를 갱신하거나 메시지를 추가하는 함수에서 게임 규칙을 분리합니다.

목표 경계(상태 타입과 대상 명령 검증은 구현, 이벤트·상태 전이는 후속 작업):

- `GameState`: 단계, 라운드, 참가자, 밤 행동과 투표, 승리 진영을 보관합니다.
- `GameCommand`: 게임 시작, 밤 행동 제출, 투표 제출, 단계 진행 요청을 표현합니다.
- `GameEvent`: 단계 변경, 공개 탈락, 개인 조사 결과, 게임 종료 등 판정 결과를 표현합니다.
- `applyCommand(state, command, context)`: 새 상태와 이벤트 또는 거절 사유를 반환합니다.
- `context`: 난수와 ID·시간 생성기를 주입합니다. 같은 입력과 같은 난수 흐름이면 같은 결과를 얻도록 합니다.

규칙 엔진에는 React, DOM, 저장소, 네트워크 접근을 넣지 않습니다. `useMafiaGame`은 엔진 호출, 화면 상태, 프로필 보존을 연결합니다. 기존 NPC가 고른 대상도 같은 명령 검증을 통과하도록 합니다.

완료 기준:

- 참가자 수별 역할 구성과 기존 승패 조건을 유지합니다.
- 의사 보호, 형사 조사, 밤 공격, 최다 득표 탈락, 동률 시 무탈락을 테스트합니다.
- 사망자 행동, 자기 투표, 존재하지 않는 대상, 잘못된 단계의 명령을 거절합니다. 의사의 자기 보호는 허용합니다.
- 마지막 행동의 수치를 결과·업적에 포함하고 XP·프로필 갱신은 게임 종료당 한 번만 수행합니다.
- 기존 솔로 화면과 저장된 프로필을 계속 사용할 수 있습니다.

## 2단계: 참가자별 정보 분리

`projectForViewer(state, viewerId)`가 화면과 NPC에 제공할 정보를 만듭니다. 전체 `Player[]`를 클라이언트 응답에 넣지 않습니다.

| 정보 | 허용 대상 |
| --- | --- |
| 이름, 생존 여부, 단계, 라운드, 공개 대화 | 해당 방 참가자 |
| 자신의 역할 | 본인 |
| 형사 조사 결과 | 조사한 형사 |
| 팀원 마피아의 정체 | 초기 버전에서는 추가 공개하지 않음. 도입 시 별도 룰 변경 필요 |
| 미제출·제출된 밤 행동 대상 | 해당 행동 주체와 판정 서버 |
| 투표 선택 | 투표 종료 전에는 본인, 집계 후에는 방 참가자 |
| 전체 최종 역할 | 게임 종료 후 방 참가자 |

로그도 공개 이벤트와 개인 이벤트를 구분합니다. 화면에서 숨기더라도 응답 JSON에 비밀 정보가 있으면 실패로 판단합니다. 종료된 게임의 전체 로그를 허용하더라도 재접속용 활성 게임 로그와 섞지 않습니다.

완료 기준은 서로 다른 두 참가자의 상태와 로그 응답을 비교하는 정보 노출 테스트입니다. 방 참가자가 아닌 요청에는 상태·로그를 반환하지 않습니다.

## 3단계: 선택형 LLM 대사

첫 AI 도입 범위는 낮의 일반 발언과 심문 응답입니다. 투표 대상, 밤 행동, 승패, XP는 기존 규칙 기반 로직이 결정합니다. 대사는 추가 선택 기능으로 제공하며 연결 실패 시 기존 한국어 대사를 사용합니다.

처리 흐름:

1. 서버에서 요청자, 방, 단계, 발언 대상 NPC를 확인합니다.
2. NPC의 성격, 자신에게 허용된 역할 정보, 공개 사건과 제한된 최근 대화만 입력으로 구성합니다.
3. 어댑터를 통해 대사를 요청하고 길이·형식·금지 정보 노출을 검사합니다.
4. 같은 게임·라운드·발언 요청 ID의 결과를 재사용합니다. 응답 전에 단계가 바뀌면 오래된 결과를 버립니다.
5. 제한 시간 초과, 요청 제한, 응답 검증 실패 시 규칙 기반 대사를 반환합니다.

사용자 대화는 지시가 아닌 게임 데이터로 취급합니다. 모델에 다른 참가자의 전체 역할표, 저장 프로필, 개인 조사 결과를 전달하지 않습니다. NPC 자신의 역할을 알고 거짓말하는 경우에도 역할명이나 비공개 필드가 그대로 출력되는 경로는 별도로 검증합니다. 문장 검사만으로 모든 정보 유출을 보장할 수 없으므로 입력 정보 최소화와 시나리오 평가를 함께 적용합니다.

공급자·모델·예산은 아직 미선정입니다. 한국어 대사 품질, 응답 시간, 요청당 비용, 구조화된 출력 지원 여부를 비교해 확정합니다. 키는 서버 환경 변수로만 관리하고 실제 연동 시 비밀값을 제외한 설정 이름을 `.env.example`에 추가합니다.

완료 기준:

- AI 설정과 키가 없어도 솔로 게임을 끝까지 진행할 수 있습니다.
- 한 발언의 중복 클릭·재시도는 중복 과금 요청과 중복 메시지를 만들지 않습니다.
- 요청별 출력 한도, 방별 호출 한도, 제한 시간과 전체 예산 상한을 설정합니다.
- 프롬프트 주입, 역할 공개 유도, 장문·빈 응답, 장애, 단계 변경 중 응답을 평가합니다.

## 4단계: 서버 기반 하이브리드 방

초기 범위는 초대 코드로 입장하는 비공개 방과 빈자리를 채우는 규칙 기반 NPC입니다. LLM 없이도 방을 진행할 수 있어야 합니다. 계정·랭킹·공개 매칭·신규 역할은 이 단계에 포함하지 않습니다.

서버가 역할 배정, 명령 검증, 단계 마감, 난수와 승패를 결정합니다. 방장은 시작만 요청하며 다른 참가자의 행동이나 역할을 변경할 수 없습니다.

| 항목 | 초기 동작 제안 |
| --- | --- |
| 입장·시작 | 대기 중에만 입장 가능. 방장이 시작하면 빈자리를 NPC로 채움 |
| 명령 중복 | `commandId`로 중복 제거. 같은 ID의 다른 내용은 거절 |
| 순서 충돌 | `expectedRevision`으로 상태 버전 확인. 충돌 시 새 상태를 받아 재시도 |
| 단계 마감 | 서버가 마감 시간을 보관. 모든 필수 행동 제출 또는 마감 도달 시 한 번만 판정 |
| 행동 미제출 | 투표는 기권, 밤 능력은 미사용. 별도 자동 대상 선택은 하지 않음 |
| 연결 끊김 | 현재 단계 마감까지 자리 유지, 이후 NPC가 임시 대행 |
| 재접속 | 동일 참가자 세션을 검증한 뒤 허용된 상태와 마지막 이벤트 순번부터 복구 |
| 대행 후 복귀 | 진행 중 판정과 충돌하지 않도록 다음 단계부터 본인이 조작 |
| 방장 이탈 | 남은 사람에게 방장 권한 이전. 시작 후에는 서버가 게임 진행 유지 |
| 보상 | 초기 혼합 모드는 XP·일일 보상 지급 제외. 서버 보상 검증 설계 후 도입 |

실시간 전송 수단과 저장소는 미선정입니다. 구현 전 배포 환경에서 연결 유지, 재접속, 예약된 단계 마감, 원자적 갱신과 비용을 검증해 결정합니다. 이벤트는 순번으로 복구하고, 재전송되더라도 화면과 상태에 한 번만 적용합니다.

완료 기준은 두 브라우저와 NPC가 참가한 한 판을 종료하는 것입니다. 중복 투표, 동시 마감, 재접속, 이전 단계의 요청 재전송, 타 참가자 사칭을 함께 검증합니다.

## 구현 순서와 작업 단위

| 순서 | 작업 단위 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| A (완료) | 내부 상태·대상 명령 타입과 역할 구성·승패·대상 검증 분리, 솔로 훅·화면 연결 | 규칙·진행도 테스트 13개 통과 |
| B | 밤·투표 판정과 솔로 훅 연결 | 앱 검증, 업적 회귀 테스트, 솔로 한 판 확인 |
| C | 참가자별 공개 상태·로그 분리 | 역할·개인 조사·밤 행동 정보 노출 테스트 통과 |
| D | 공급자 중립 대사 어댑터와 가짜 응답 구현 | 실제 API 없이 성공·실패·중복·취소 흐름 확인 |
| E | 공급자·예산 결정 및 선택형 LLM 연동 | 한국어 품질·지연·정보 노출 평가, 장애 시 대체 흐름 확인 |
| F | 서버 방 상태와 규칙 기반 NPC 혼합 모드 | 동시성·세션·재접속 검증 및 두 브라우저 한 판 확인 |

각 단위마다 앱 코드 변경은 `npm run verify`와 관련 회귀 테스트, 문서 변경은 `npm run docs:build`로 검증합니다. 신규 의존성과 외부 서비스는 실제 구현 단위에서 필요성을 확인한 뒤 도입합니다. 현재 게임 버전은 v1.2.5입니다. 다음은 작업 단위 B이며, 서버 명령 실행·인증·중복 제거는 아직 제공하지 않습니다.
