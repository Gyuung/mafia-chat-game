# 대사 어댑터 내부 계약

v2 작업 D의 대사 준비 계층, E1의 예산 예약, E2의 서버 측 예약·호출 및 선택형 OpenAI HTTP 어댑터입니다. 조정기와 예산을 연결했으며 현재 게임 훅에는 연결하지 않았습니다. 게임은 기존 규칙 기반 대사를 사용합니다. OpenAI 요청 코드는 서버에만 있고 자동 실행하지 않으며 실제 키·모델·운영 예산은 미설정입니다. 테스트는 모의 공급자·HTTP 응답만 사용합니다.

## 모듈과 책임

| 파일 | 책임 |
| --- | --- |
| `dialogue/types.ts` | 모델 입력·공급자 인터페이스·결과 타입 |
| `dialogue/context.ts` | 신뢰할 수 있는 게임 상태에서 NPC용 최소 입력 생성 |
| `dialogue/coordinator.ts` | 요청 중복 제거, 시간 제한, 응답 검증, 취소 및 단일 결과 소비 |
| `dialogue/budget.ts` | 요청 전 입력·출력 최대 비용 예약, 예산·토큰·요청 수 상한 검사 |
| `src/server/dialogue/metered-provider.ts` | 토큰 계산 후 예산 예약, 승인한 신규 요청만 생성하고 출력 토큰 상한 전달 |
| `src/server/dialogue/openai-provider.ts` | OpenAI 입력 토큰 조회·구조화 응답 생성 HTTP 어댑터, 키 미설정 시 비활성 |
| `src/server/dialogue/request-handler.ts` | HTTP 입력·인증 결과·게임 접근·최신 단계 검사 후 대사 조정기 호출 |
| `tests/fixtures/fake-dialogue-provider.ts` | 성공·오류·지연을 제어하는 테스트 전용 공급자 |

인증 결과에 따른 게임 접근 검사와 HTTP 처리기는 구현했습니다. 실제 로그인 서비스·영속 게임/예산 저장소·공개 라우트·UI 연결, 운영 모델·단가·예산 확정은 후속 작업 E2·F에 남아 있습니다. 인증·저장소 구현 없이 이 모듈을 그대로 공개 API로 노출하지 않습니다.

## 입력 경계

`buildDialogueContext`에는 권한 확인을 마친 내부 게임 상태를 전달합니다. 낮·투표 단계의 살아 있는 NPC만 발언 대상으로 허용합니다. 심문은 살아 있는 다른 참가자의 요청과 길이 제한을 통과한 질문이 있어야 합니다.

공급자 입력은 자신의 이름·역할·성격, 공개 참가자의 ID·이름·생존 상태, 최근 공개 대화와 질문으로 제한합니다. 다른 참가자의 역할·신뢰도·의심도, 전체 밤 행동·투표 맵, 저장 프로필을 포함하지 않습니다. 해당 NPC 자신의 조사 결과와 역할 안내를 포함한 모든 개인 로그도 모델 대화 입력에서 제외합니다.

- 공개 대화는 최근 12개, 각 본문은 최대 400자, 표시 이름은 최대 40자로 제한합니다.
- 심문 질문은 빈 내용을 거절하고 400자를 넘으면 거절합니다.
- 고정 지침과 사용자 질문·대화 데이터를 별도 필드로 전달합니다. 질문을 지침 문자열에 합치지 않습니다.
- 문자 제한은 JavaScript 문자열 길이 기준입니다. 실제 공급자의 토큰 한도는 E에서 별도로 설정합니다.

입력 분리와 기본 응답 검사만으로 모든 프롬프트 주입·역할 유출을 막는다고 보장하지 않습니다. 실제 모델 도입 전 한국어 대사·우회 표현·정보 노출 평가가 필요합니다.

## 요청 생명주기

`createDialogueCoordinator`는 게임 하나당 한 인스턴스로 만듭니다. 같은 게임에서 요청 ID는 재사용하지 않고, 동일 요청 재시도에만 같은 ID·문맥·대체 대사를 사용합니다.

1. `buildDialogueContext`로 입력을 만들고 무효 요청이면 중단합니다.
2. 기존 규칙 로직에서 대체 대사를 한 번 선택합니다.
3. `request({ requestId, context, fallback })`를 호출합니다.
4. 응답을 기다린 뒤 `claim(requestId)`가 반환한 결과만 메시지에 추가합니다.
5. 단계 변경·취소 시 `cancel(requestId)`, 게임 리셋·종료·연결 해제 시 `dispose()`를 호출합니다.

`request`는 동시 호출과 완료 후 재시도에도 같은 작업의 결과를 재사용합니다. 같은 ID에 다른 문맥이나 대체 대사를 보내면 `conflict`로 거절합니다. 요청 당시 입력과 대체 대사를 복사해 보관하며 공급자에는 별도 입력 복사본을 전달합니다.

공급자의 `generate(input, { signal, requestId })`에는 조정기에 등록한 요청 ID가 전달됩니다. 서버의 예산 연결 공급자는 같은 ID로 예약하며 브라우저가 보낸 임의 ID를 그대로 승인하는 기능은 아닙니다.

`request`의 완료 결과를 직접 화면에 추가하면 호출자마다 중복 표시할 수 있습니다. 게시에는 반드시 `claim`을 사용합니다. 같은 ID의 결과는 한 번만 가져갈 수 있으며, 소비 시점에도 현재 단계인지 확인합니다. 완료 결과는 호출자가 바꾸지 못하도록 동결합니다.

## 제한과 결과

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `timeoutMs` | 3000 | 공급자 응답을 기다리는 제한 시간 |
| `maxOutputChars` | 280 | 공급자 응답과 준비된 대체 대사의 길이 상한 |
| `maxRequests` | 40 | 게임 인스턴스에서 승인·보관하는 고유 요청 수 상한 |
| `isCurrent` | 필수 콜백 | 게임 ID·라운드·단계가 여전히 유효한지 판단 |

`isCurrent`는 변경 가능한 최신 상태를 읽어 판단해야 합니다. 요청 시작 전·응답 처리 시·게시 소비 시에 검사합니다. 단계가 바뀌면 호출자가 취소해 대기도 중단할 수 있고, 취소하지 않더라도 늦은 응답은 폐기합니다.

| 경우 | 결과 |
| --- | --- |
| 정상 공급자 응답 | `ready`, `source: provider` |
| 공급자 없음 | `ready`, 기존 대사와 `disabled` |
| 공급자 예외·시간 초과·잘못된 출력 | `ready`, 기존 대사와 정해진 오류 코드 |
| 취소·이전 단계·게임 폐기 | `discarded`, 메시지를 추가하지 않음 |
| 다른 게임·빈 ID·잘못된 요청 | `discarded`, 공급자를 호출하지 않음 |
| 요청 상한 초과 | `discarded`, `capacity`; 새 작업은 승인하지 않음 |

공급자의 원본 오류 메시지는 반환하지 않습니다. 응답은 `text` 문자열 하나만 가진 객체여야 하며, 빈 내용·장문·제어 문자·코드 블록·명시적인 역할 자백 패턴은 대체 대사로 바꿉니다. 이는 제한적인 형식·패턴 검사이며 의미 기반 검증을 대신하지 않습니다.

시간 초과·취소 시 `AbortSignal`을 중단합니다. 공급자가 이를 무시하더라도 조정기는 기다림을 끝내고 늦은 응답을 게시하지 않습니다. 이미 시작된 외부 호출의 비용까지 취소되는 것은 아니므로 실제 공급자 계약과 SDK 정책을 확인해야 합니다.

캐시에서 승인된 ID를 중간 삭제하지 않습니다. 삭제 후 재시도하면 중복 호출할 수 있기 때문입니다. 상한에 도달하면 새로운 ID를 거절하고, 종료 시 `dispose()`가 모든 보관 작업을 정리합니다. 상한 초과 후 규칙 기반 게임 흐름을 계속하는 정책은 UI 연결 단계에서 구현합니다.

이 중복 제어는 한 인스턴스의 메모리 범위입니다. 서버 재시작·다중 프로세스·다중 장비의 중복 방지 및 영속 예산 관리는 서버 단계에서 추가합니다.

## E1: 호출 전 예산 예약

`createDialogueBudget(limits)`는 게임 하나의 예산 장부입니다. E2의 서버 공급자 래퍼를 통해 조정기와 연결할 수 있으며 공개 엔드포인트·UI에는 연결하지 않았습니다. 운영 예산·공급자·단가를 기본값으로 정하지 않고 호출자가 명시하도록 합니다.

| 설정 | 단위·의미 |
| --- | --- |
| `maxRequests` | 승인·보관하는 고유 요청 수 |
| `maxInputTokens` | 한 요청의 전체 입력 토큰 상한 |
| `maxOutputTokens` | 한 요청의 출력 토큰 상한 |
| `maxReservedMicroUsd` | 게임 전체 예약 상한, 1 USD = 1,000,000 마이크로달러 |
| `inputMicroUsdPerMillionTokens` | 입력 백만 토큰당 마이크로달러 |
| `outputMicroUsdPerMillionTokens` | 출력 백만 토큰당 마이크로달러 |

요청 수·토큰 상한은 양의 안전한 정수, 금액·단가는 0 이상의 안전한 정수만 허용합니다. 입력 비용과 출력 최대 비용을 각각 마이크로달러 단위로 올림해 합산하며, 곱셈은 `BigInt`로 계산합니다. 소수 단가는 충분히 올림한 정수로 전달해야 합니다.

서버 연결 시 호출 순서는 다음과 같습니다.

1. 요청자·방·단계를 인증·검증하고 신뢰할 수 있는 상태에서 대사 입력을 생성합니다.
2. 고정 지침·질문·메타데이터를 포함한 최종 모델 입력 전체를 공급자 토크나이저로 계산합니다. 문자 수를 토큰 수로 취급하지 않습니다.
3. 서버가 만든 요청 ID와 입력의 안정적인 지문, 입력 토큰 수로 `reserve`를 호출합니다. ID·지문은 각각 1~128자이며 공백만 있는 값은 거절합니다. 지문에는 게임·단계·발언자·입력·모델과 생성 설정을 포함해야 합니다.
4. `rejected`이면 외부 호출 없이 기존 대사로 진행합니다. 예산 부족은 `budget`, 토큰 초과는 `input-limit`, 요청 수 초과는 `capacity`, 동일 ID의 다른 내용은 `conflict`입니다.
5. `reserved`의 `duplicate: false`일 때만 새로운 외부 호출을 시작합니다. `duplicate: true`는 기존 요청·결과를 찾아 재사용하라는 뜻이며 재호출 권한이 아닙니다. 장부는 응답을 캐시하지 않으므로 조정기·영속 요청 저장소와 함께 연결해야 합니다.
6. 실제 공급자의 출력 토큰 제한을 예약 결과의 `maxOutputTokens`로 설정합니다. 기존 `maxOutputChars`는 별도의 표시 길이 제한입니다.

동기적으로 비용을 예약하므로 같은 인스턴스의 동시 진입은 중복 차감하지 않습니다. 예산·요청 수가 소진된 후에도 동일 요청은 예약을 재사용합니다. 원래 입력 토큰 수나 지문이 달라지면 충돌입니다. 예약·통계는 복사·동결하고 설정도 생성 시 복사합니다.

실패·취소·시간 초과·짧은 응답에도 예약을 환급하지 않습니다. 승인 ID는 중간 삭제하지 않으며 상한에 도달하면 새 ID를 거절합니다. 재시도마다 새 ID를 만들거나 게임 중 새 장부를 만들면 중복 방지·상한이 무효화되므로 같은 게임에 한 장부를 유지해야 합니다.

이 장부는 메모리 한 인스턴스의 보수적인 예약 합계입니다. 실제 청구액·과금 취소·서버 재시작·여러 프로세스의 원자성까지 보장하지 않습니다. 공급자별 추가 과금·추론 토큰·자동 재시도는 예약식에 포함하거나 비활성화해야 하며, 실제 단가·토크나이저·출력 제한과 인증·영속 원자적 저장소 연결 전에는 공개 유료 엔드포인트로 사용할 수 없습니다.

## E2: 조정기와 예산을 연결하는 서버 공급자

`createMeteredDialogueProvider`를 조정기의 `provider`로 전달합니다. Node 서버 전용 모듈이며 공개 API·인증·영속 저장소를 제공하지 않습니다. 인스턴스는 게임별 장부와 함께 유지합니다.

- `gameId`: 이 공급자가 처리하는 게임 식별자입니다. 다른 게임의 입력은 토큰 계산 전에 거절합니다.
- `providerKey`: 공급자·모델·직렬화·생성 설정의 버전을 나타내는 1~128자 식별자입니다. API 키가 아닙니다. 모델이나 생성 설정이 바뀌면 이 값도 바꿉니다.
- `budget`: 해당 게임의 예산 장부입니다. 재시도·조정기 재생성 때에도 같은 장부를 유지해야 합니다.
- `isCurrent`: 최신 게임·라운드·단계를 검사합니다. 조정기와 같은 기준을 사용하며 토큰 계산 전후에 검사합니다.
- `prepare(input, { signal })`: 유료 생성을 시작하지 않고, 지침·문맥·모든 공급자 메타데이터가 포함된 최종 입력을 준비합니다. `inputTokens`와 `invoke({ signal, maxOutputTokens })`를 반환합니다.

래퍼는 입력을 복사하고 `providerKey`와 입력 전체의 SHA-256 지문을 만듭니다. 준비가 끝나면 취소 신호·현재 단계를 재확인하고 동기적으로 비용을 예약합니다. 승인한 신규 요청만 `invoke`를 한 번 실행하며 예약 결과의 출력 토큰 상한을 전달합니다. 공급자 어댑터는 실제 API에도 이 상한을 적용하고 자동 생성 재시도를 하지 않아야 합니다.

동일 요청의 결과 재사용과 단일 표시는 조정기의 `request`·`claim`이 담당합니다. 장부에는 승인 ID가 있지만 조정기에는 결과가 없는 경우(예: 조정기만 재생성)에는 외부 생성을 다시 하지 않고 기존 대사를 반환합니다. 서버 재시작 이후 결과 복구는 영속 요청 저장소의 후속 책임입니다.

토큰 계산 중 취소·시간 초과·단계 변경은 예약·생성을 하지 않습니다. 생성이 이미 시작된 후 실패·시간 초과·응답 검사 실패는 예약 금액을 유지합니다. 예산·토큰 상한 거절 및 장부의 중복·충돌은 조정기에서 기존 대사와 일반 `provider-error`로 처리하며 내부 오류 내용을 노출하지 않습니다.

OpenAI를 첫 선택형 어댑터로 구현했으며 운영 공급자·모델·단가·예산은 아직 확정하지 않았습니다. 공통 연결 테스트는 주입한 준비·생성 함수를 사용합니다.

## 선택형 OpenAI 어댑터

`createOpenAiDialogueProvider({ gameId, budget, isCurrent, apiKey, model })`가 공통 조정기에 전달할 공급자를 만듭니다. `apiKey`가 없거나 공백이면 `undefined`를 반환하여 조정기가 기존 대사와 `disabled`를 반환합니다. 키가 있는데 모델이 없거나 설정 형식이 잘못되면 초기화 시 거절합니다. 모델과 단가는 기본값으로 정하지 않습니다.

서버 연결 시 `.env.example`의 `OPENAI_API_KEY`·`OPENAI_DIALOGUE_MODEL`을 서버 환경에서 읽어 전달합니다. 실제 비밀값은 저장소·브라우저·채팅에 넣지 않습니다. 현재 환경 변수를 자동으로 읽거나 공급자를 생성하는 공개 엔드포인트·화면은 없으므로 두 변수만 설정해도 게임의 AI 대사가 켜지지 않습니다.

처리 순서:

1. 고정 지침·문맥·표시 길이·응답 JSON 스키마를 포함한 동일 입력으로 `POST /v1/responses/input_tokens`를 호출합니다.
2. 반환한 입력 토큰 수를 장부에 전달합니다. 무효 응답·예산/토큰 상한 초과면 생성 API를 호출하지 않습니다. 토큰 조회 자체는 네트워크 요청이며 조정기 제한 시간에 포함합니다.
3. 새 예약을 승인하면 같은 입력에 `max_output_tokens`를 추가해 `POST /v1/responses`를 한 번 호출합니다. `store: false`·`stream: false`를 지정하고 도구·대화 이력 연결·자동 재시도는 사용하지 않습니다.
4. 완료 상태의 단일 assistant 메시지에서 `output_text` JSON을 읽습니다. 미완료·거절·도구 호출·복수 메시지·잘못된 JSON은 거절합니다. 공통 조정기가 길이·역할 공개·추가 필드를 다시 검사합니다.

인증 헤더는 고정된 `https://api.openai.com`에만 전송합니다. 리디렉션을 거절하고 캐시를 비활성화하며 각 HTTP 응답은 최대 32 KiB로 제한합니다. 원본 HTTP·네트워크 오류나 키는 반환 예외·게임 메시지에 포함하지 않습니다. 취소 신호는 토큰 조회와 생성 모두에 전달합니다.

공식 계약 확인 자료(2026-11-20): [입력 토큰 조회](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count), [Responses 생성](https://developers.openai.com/api/reference/resources/responses/methods/create), [토큰 계산 안내](https://developers.openai.com/api/docs/guides/token-counting).

운영 전에는 선택 모델의 구조화 출력·입력 토큰 조회 지원, 현재 단가와 출력/추론 토큰 과금, 실제 한국어 응답 품질·지연·정보 노출을 평가해야 합니다. 실제 키를 사용한 호출은 이번 검증에 포함하지 않았습니다. 인증·영속 요청/예산 저장소를 연결한 후 서버 API·UI를 연결합니다.

## 서버 대사 요청 접근 검증

`createDialogueRequestHandler`는 Web `Request`를 받아 `Response`를 반환하는 내부 처리기입니다. 현재 Next.js의 공개 Route Handler에는 등록하지 않았습니다. 로그인 서비스·서버 게임 저장소도 아직 연결하지 않았으며, 테스트는 검증된 세션을 돌려주는 모의 인증 함수와 메모리 게임을 주입합니다.

호출자가 제공할 항목:

- `origin`: 배포 앱의 정규 출처 하나입니다. 경로·후행 슬래시 없는 `https://example.com` 형태이며 요청 URL과 Origin 헤더 모두 같은 출처여야 합니다.
- `authenticate(request)`: 쿠키·토큰을 실제로 검증해 `{ playerId }` 또는 `null`을 반환합니다. 클라이언트가 보낸 참가자 ID를 그대로 신뢰하는 구현은 사용할 수 없습니다. 본문은 읽지 않습니다.
- `loadGame(gameId)`: 서버가 보유한 같은 게임 ID·상태·내부 메시지·공유 조정기를 반환합니다. 요청마다 조정기나 예산 장부를 새로 만들지 않습니다. 게임 ID는 다른 게임에 재사용하지 않습니다.
- `fallback`: 재시도에도 같은 값을 유지할 대체 대사입니다. 1~280자이며 조정기에 설정한 표시 상한도 만족해야 합니다. 모델·클라이언트가 정하지 않습니다.

허용 본문 예시:

```json
{
  "gameId": "game-1",
  "requestId": "speech-1",
  "speakerId": "npc-1",
  "kind": "interrogation",
  "expectedRound": 1,
  "expectedPhase": "day",
  "question": "어젯밤 어디에 있었나요?"
}
```

ID는 앞뒤 공백·제어 문자 없는 1~128자입니다. `kind`는 `discussion` 또는 `interrogation`, 예상 단계는 `day` 또는 `vote`, 라운드는 양의 안전한 정수입니다. 심문에만 400자 이하의 질문 문자열을 허용하며 일반 발언의 질문 필드, 역할·전체 상태·행위자 ID 등 허용 목록 밖 필드는 거절합니다.

POST JSON만 받고 본문은 최대 4096바이트입니다. Content-Length가 작게 표시되거나 없어도 실제 스트림 크기를 검사합니다. 인증 전에는 게임을 조회하지 않으며, 존재하지 않는 게임과 비참가자·NPC 사칭에는 같은 응답을 사용합니다. 요청자는 살아 있는 사람 참가자여야 하고 대상은 살아 있는 NPC여야 합니다. 심문 행위자는 세션에서 가져오며 권한 검사 후 `buildDialogueContext`로 최소 입력을 만듭니다.

참가자·게임·원래 요청 ID의 SHA-256 값을 조정기 ID로 사용해 다른 참가자의 같은 ID와 충돌하지 않게 합니다. 서버 문맥까지 동일한 재요청은 조정기의 기존 결과를 재사용합니다. 같은 ID라도 질문이나 공개 문맥이 바뀌면 충돌로 거절하며, 생성 API를 다시 호출하지 않습니다. 변경된 문맥에서도 원래 응답을 복구하는 영속 요청·입력 스냅샷 저장은 후속 작업입니다.

생성 대기 후에는 인증과 최신 게임을 함께 다시 조회해 세션 만료·사칭·퇴장·탈락·단계 변경을 재검사합니다. HTTP 연결 하나의 취소로 공유 조정기 작업을 취소하지는 않습니다. 중복 연결의 정상 응답과 캐시를 보존하기 위해서이며 게임 종료·단계 변경 시 취소/폐기는 게임 실행 계층이 담당합니다.

| 상태 | 의미 |
| --- | --- |
| 200 | `{ requestId, text, source }`만 반환. 공급자 장애·비활성은 기존 대사로 대체 |
| 400 / 413 / 415 | 무효 입력 / 본문 상한 초과 / JSON 외 형식 |
| 401 / 403 / 404 | 인증 실패 / 출처·생존 조건 불충족 / 게임·참가 접근 불가 |
| 408 / 409 / 410 / 429 | 연결 취소 / 단계·내용 충돌 / 조정기 폐기 / 요청 상한 |
| 405 / 500 | POST 외 메서드 / 내부 처리 실패 |

응답은 캐시하지 않으며 원본 인증·저장소 오류, 역할표와 개인 로그를 반환하지 않습니다. 처리기는 HTTP 전달만 담당해 `claim`을 소비하거나 메시지·게임 상태를 저장하지 않습니다. 후속 서버 이벤트 저장·UI는 같은 요청을 한 번만 반영하도록 연결해야 합니다. 운영 로그인·권위 있는 게임 상태·원자적 영속 요청/예산 저장소·요청 속도 제한을 연결한 후 공개 라우트와 UI를 활성화합니다.
